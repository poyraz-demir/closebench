# closebench — по-русски

Детерминированные seeded-книги двойной записи с посаженными ошибками закрытия месяца
и программной проверкой результата. Зависимостей ноль. Для тестирования бухгалтерских
агентов.

Полное описание, таксономия ошибок и семантика оценки — в корневом `README.md`
(английский). Здесь только то, что важно русскоязычному пользователю.

## Локаль

```python
from closebench.world import World
World(seed=7, lang="ru").build()     # русские названия счетов, документы, политика
World(seed=7, lang="en").build()     # то же самое по-английски
```

Числа, даты, счета, состав ошибок и месяцы пропусков у обеих локалей **одинаковы**
для одного seed. Отличается только текст.

```bash
closebench --session demo --start 7 --lang ru
```

## Режимы

- seed < 1000 — `hard`: 6–9 ошибок из семнадцати типов, документы-улики, ловушки,
  двойники-пустышки;
- seed ≥ 1000 — `absence`: 4–6 ошибок только типа «отсутствие», спрятанных
  в случайном месяце года, а не в месяце закрытия.

## Что это и чем не является

Это **регрессионный набор**, а не трудный бенчмарк. Фронтир-модель с нейтральным
заданием проходит `hard` на 83 %, `absence` — на 58 % (92 %, если засчитать отказ
проводить недокументированный приход товара). Ловушки не ловят никого. Используйте
балл, чтобы ловить регрессии собственного агента, а не чтобы ранжировать модели.

Единственное, что модели стабильно делают неверно: две ошибки, которые гасят друг друга
в сальдо (пропущенный резерв и непогашенный резерв той же суммы). Это по-прежнему
две ошибки.
